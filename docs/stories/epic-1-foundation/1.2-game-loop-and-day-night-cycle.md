# Description

Implement the core game loop state machine and day/night cycle system that drives the fundamental "Day → Build → Night → Survive → Upgrade" gameplay loop. This story builds upon the foundation services from Story 1.1 to create the time-based progression system that controls game phases and player activities.

This story references PRD functional requirements FR8 (game loop state transitions) and FR12 (day/night cycle with visible timer), supporting the core 15-minute rogue-lite session structure defined in the Goals section.

## Class/Interface Definitions

```csharp
// GamePhase - Defines the main game phases
public enum GamePhase
{
    Day,
    Build,
    Night,
    WaveInProgress,
    EndWave
}

// IGameLoopManager - Game loop management interface
public interface IGameLoopManager : IService
{
    GamePhase CurrentPhase { get; }
    float PhaseTimeRemaining { get; }
    float PhaseProgress { get; }
    bool IsPaused { get; }
    
    void StartGameLoop();
    void PauseGameLoop();
    void ResumeGameLoop();
    void ForcePhaseTransition(GamePhase targetPhase);
    
    event System.Action<GamePhase, GamePhase> OnPhaseChanged;
    event System.Action<float> OnPhaseTimeUpdated;
}

// GameLoopManager - Core game loop implementation
public class GameLoopManager : MonoBehaviour, IGameLoopManager
{
    [SerializeField] private GameLoopConfig config;
    private GameLoopState currentState;
    private Dictionary<GamePhase, GameLoopState> states;
    private GameTimer gameTimer;
    
    public void StartGameLoop();
    public void TransitionToPhase(GamePhase phase);
    private void Update();
}

// IDayNightCycle - Day/night visual and timing interface
public interface IDayNightCycle : IService
{
    float DayProgress { get; }
    bool IsDay { get; }
    Color CurrentAmbientColor { get; }
    
    void SetTimeOfDay(float normalizedTime);
    event System.Action<float> OnTimeOfDayChanged;
}

// GameLoopConfig - Configuration for game loop timing
[CreateAssetMenu(fileName = "GameLoopConfig", menuName = "Game/Game Loop Config")]
public class GameLoopConfig : ScriptableObject
{
    [Header("Phase Durations (seconds)")]
    public float dayPhaseDuration = 180f;     // 3 minutes
    public float buildPhaseDuration = 120f;   // 2 minutes
    public float nightPhaseDuration = 60f;    // 1 minute
    public float waveProgressDuration = 300f; // 5 minutes
    public float endWaveDuration = 30f;       // 30 seconds
    
    [Header("Day/Night Visual Settings")]
    public Color dayAmbientColor = Color.white;
    public Color nightAmbientColor = new Color(0.3f, 0.3f, 0.5f);
    public AnimationCurve lightTransitionCurve;
}
```

# Game Design Context

**GDD Reference:** PRD Goals (15-minute sessions), FR8 (game loop transitions), FR12 (day/night cycle)

**Game Mechanic:** Core time-based progression system driving player activities

**Player Experience Goal:** Clear, predictable phases that create rhythm and tension in the "Day → Build → Night → Survive → Upgrade" loop

**Balance Parameters:**

- Day phase: 3 minutes (resource gathering time)
- Build phase: 2 minutes (strategic planning time)
- Night phase: 1 minute (preparation for combat)
- Wave progress: 5 minutes (combat duration)
- End wave: 30 seconds (upgrade selection time)
- Total cycle: ~11.5 minutes (allows multiple cycles in 15-minute session)

# Notes

**Implementation Notes:**

- GameTimer should use Time.unscaledTime for pause-resistant timing
- State transitions should be atomic to prevent race conditions
- Day/night visual transitions should use coroutines for smooth interpolation
- Configuration should support runtime modification for balancing

**Design Decisions:**

- Separate GameLoopManager from GameManager for single responsibility
- ScriptableObject configuration enables easy balancing without code changes
- Event-driven architecture allows loose coupling with future systems
- Phase-based state machine provides clear structure for complex game loop

**Future Considerations:**

- Phase durations could scale based on player progression or difficulty
- Additional micro-phases could be added within main phases
- Weather system could integrate with day/night cycle
- Seasonal variations could modify phase characteristics
